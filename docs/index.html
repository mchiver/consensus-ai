Consensus-AI

Plans you and your LLM actually agree on.

Consensus-AI turns a draft into a plan your LLM can build, one settled question at a time.

Get started Read the guide

You have had this conversation before.

Working a design out with an LLM is fast, until it is not.

Decisions buried in a chat scroll

You settled that question an hour ago. Now it is forty messages up, and the model has forgotten it.

The wrong thing, built confidently

One sentence read two ways. The model picked one, built it beautifully, and now you are unpicking it.

No record of what was agreed, or why

The plan that was built is not the plan you have. The reasons are somewhere in a conversation nobody will reread.

How it works

A plan is a document with threads. Each thread is one question, settled in one place, and applied to the text in front of you.

1

Write a draft

Markdown, in an editor with a live preview. Rough is fine: the draft is where the questions come from, not the answers.

2

Settle it thread by thread

Select a passage and comment. The LLM replies. You resolve. It applies the outcome to the text, and the thread turns green with the revision it made.

3

Build it

The plan is done when every thread is applied. Say "build it": your agent implements exactly that plan, and its build log is a thread too, accepted the same way.

What you get

A record you can trust, and an LLM that only does what you settled.

  • Every decision is anchored to the words it changed, and the anchor follows the text as it evolves.
  • The LLM applies only what you resolved. Nothing goes into the plan that you did not agree to.
  • Revisions and applied records are the history. There is no change log to keep, because the plan keeps itself.
  • Works with Claude Code and other agents, with Claude, ChatGPT, Gemini and Grok through their APIs, and with local models through Ollama.
  • Your data is plain files in a folder you own. Back it up by copying it.

Where it runs

On your machine, on a server of yours, or in a window of its own.

The applications

The Sidecar for a folder of your own with your agent beside it, no account needed; the Client for one project on a Server; the Desktop for several Servers at once, signed in once.

The Server

One server for several people, in a window of its own or headless: the projects, the users and their roles, the LLM connections and tasks.

Docker

One image, one volume, port 3500. Put it on a box on your network and work from anywhere on it.

Get started

The code is public at github.com/mchiver/consensus-ai. Four ways to run it.

From the checkout

Node 22 and git

Clone, install, and start the Server.

git clone https://github.com/mchiver/consensus-ai.git
cd consensus-ai
npm install
npm run server

Sign in on its page with a Personal license to become its Administrator. More in the guide.

In Docker

One image, one volume

Build the image from the checkout; the data lives in its volume.

docker build -t consensus:latest .
docker compose up -d

Port 3500. More in the guide.

The applications

A window of its own

Run the Sidecar on a folder, the Client on a Server's project, or the Desktop on your Servers.

npm run sidecar -- <folder>
npm run client
npm run desktop

More in the guide.

The installer

Windows, no checkout

Consensus Sidecar, Client, Desktop and Server, each packaged: download, install, open. The installers are not signed yet, so Windows asks once before each runs.
