# Project settings

Raised by the owner on 2026-10-26 after running the Desktop: a folder opened in the Desktop showed the settings of the global config (`~/.consensus/consensus.json`) rather than the project's own. A project's `project.json` is part of the project's folder and goes into source control with it, so it holds what belongs to the project for anyone who clones it, and nothing else: never a secret, and nothing that belongs to one machine's Server or one person.

## What project.json holds

- **Kept:** Id, Name, Context, ContextFolder, Created, Updated, Version, Items, Archive, States, Include, Exclude, Commands, GitSync, AutoCommit.
- **Added:** `View`, the project's view settings (below).
- **Removed:** `Roles` and `Llm`. They name one Server's accounts and one Server's LLM connection, so they live in the user's global config only. A stray `Mounted` (the registry's switch, written back into some project.json files) is removed too.

None of what is kept is a secret.

## Where Roles and Llm go

They move onto the project's entry in the global config's project list: `consensus.json` Projects `[ { Path, Mounted, Llm, Roles } ]`. The store joins them to the project when it reads it, as it joins `Mounted` today, and writes them to the entry when they change, so the code that reads a project's roles and connection is unchanged.

## Moving existing projects

At start, a Server (a writable global config) finds a `project.json` that still has `Roles` or `Llm`, copies them to the project's entry where the entry has none, and writes `project.json` without them. The Desktop's sidecar reads the global config read-only, so it moves nothing: it ignores those fields, as it has no roles or connections in sidecar mode, and leaves them for the Server to move.

## View settings

`project.json` gets `View`: the project's look, the same for everyone who opens it.

- **In View:** the margins, the highlight, the editor, the preview and source mode, show-updated, which panes are hidden (the tree, the threads) and the pane widths.
- **Kept per person, as now** (`desktop.json` in the Desktop, the browser's storage otherwise): the open tabs, the open item and project, the folded sections, the thread filter, the closed roots, the LLM box, the comment height and the other remembered conveniences.

View is the project's starting look. A person's own changes to the look stay with that person and override the project's for them; the project's look changes only through its settings.

## The settings of a project

- **The Desktop, sidecar mode:** Settings shows the project's settings, read from and saved to `project.json`: the Name, the States, Include and Exclude, and View. The global config's settings (Port, Scope, Owner, Tasks, the Clerk section) are not shown there and are never read for it.
- **A Server:** Settings stays the Server's own. A project's settings open from the project's menu ("Project settings…"), for its Owners and the Administrator and Managers, with its LLM connection and Tasks besides.
- **The API:** the project update operation takes `View` (known keys only, plain values), and refuses `Roles` and `Llm` writes into the file.

## Steps

### Step 1: Roles and Llm leave project.json

The registry entry carries `Llm` and `Roles`; the store joins them on read and writes them to the entry; Prepare moves them out of an old `project.json` on a writable config; the sidecar ignores them; a stray `Mounted` is removed. Tests: a project.json with Roles and Llm is moved once and not again; the roles and the connection read the same before and after; the sidecar leaves the file's fields alone; a written project.json never holds Roles, Llm or Mounted.

### Step 2: View in project.json

The `View` field, its keys and defaults; the page takes the project's View as the starting look, a person's remembered value over it; the update operation takes View. Tests: View read and saved; an unknown key refused; a person's value wins over the project's.

### Step 3: The Settings of a project

The Desktop's Settings in sidecar mode shows and saves the project's settings; a Server's projects get "Project settings…". Tests, the smoke, and the guide (settings, projects, the Server) brought along.
