# Consensus Electron App

The Worker Electron App is great but it doesnt go far enough.
This Consensus App includes everything in the Consensus server UI as well the functionality from the Worker server.
We are going to combine them into a single Electron app and re-imagine how the app can look and flow in both local and remote environments.

I want an all-in-one app that has the following:
- runs a local consensus server
- connects to a remote consensus server
- The Consensus UI is available for each connected Consensus server (including local).
- a configured list of Workspaces
- a configured list of LLM connections


## Global Settings Page

- Set the host name for this server.
- Configure named LLM connections.
- Configure named Workspaces.
- Set the theme and style for everything.


## Startup Mode

Consensus can be used as a standalone app or can be run in server mode and offered to remote clients.


## Main User Interface

A simple tabbed interface of connected Consensus servers.

Each Consensus tab provides an entire Consensus Client UI:
- Project Tree
- Tabbed content area
- Threads area


## Consensus Redfined

The Consensus Project Tree will gain a built-in `Context` folder containing a single `Context` document and a number of Workspaces.

Clicking a Plan's Review or Build button will drop down a menu of valid Workspaces to direct the command to.
This will trigger a call to the Workspace's LLM and also serve the Workspaces files via tool calls or MCP to the LLM.

A Workspace becomes a kind of project item and is visualised by a tab containing the UI for a Workspace:
- Workspace Name
- LLM Connection
- Allow Review, Allow Build
- Prompts
    - Review
    - Build
- Workspace root path
    - Include
    - Exclude
- File list preview
