# Review 2026-10-29

In the beginning there was Desktop and then there was Server. Confusion occured and then Desktop was split into Sidecar and Client. There are now 4 different editions of Consensus, each with different roles and expectations.

While I do wish to maintain a clear separation between the editions, instructiions were given to abstract out similar sections and componentize them for reuse between the editions. Sidecar and Client are more recent creations and have established the pattern of reusability. Desktop and Server have not been updated and may contain outdated or contrary code.

## Findings (Claude-CLI, Claude Fable 5.1, 2026-10-29)

### How the review was done

The whole test suite was run once (305 tests: 300 pass, 2 fail, 3 skipped for want of the Clerk development keys). The four Electron apps (desktop, sidecar, client, server), the shared electron folder, the start-up modules (Start, Server, Sidecar, Host, Gate, License, Participants, Api, Instructions) and the page's edition-aware scripts (app, roots, client, session, stored, theme, tree, title-bar, project, settings, instructions) were read in full. Every exported name of every module was checked for a reader outside its module, every API operation for a caller in the page, and every page script and component for a place in index.html.

### Correctness

1. **The Server window's first sign-in throws.** In server/main.js the set-license handler stringifies the current user record before writing the new one. With no user.json yet the record is null, the text is the four letters null, and reading a field off the parsed value throws before the gate is checked again. The handler rejects, the page shows the sign-in failing, and the window's own sign-in never opens the gate until a user.json exists from elsewhere (the Desktop, or a second attempt).
2. **Two Sidecar windows on one folder are two writers of one store.** Sidecar starts its server with no address file, so the check in Start.Run that finds a folder already open never fires, and there is no Activate. Desktop has both. The Store writes its files to a temporary name without the process id (Store.js write_file), so two processes saving the same file can also collide on the temporary file.
3. **The Client's hidden menu keeps a dead item.** Windows.BuildMenu always adds Open folder in new window with Ctrl+Shift+O; the Client passes an empty function for it. The accelerator does nothing there.
4. **The Server window is the one window not built on electron/Windows.js.** It is a framed window with no title bar overlay, no chrome message, no AskToClose, no print-pdf and no view-in-browser handlers. Closing it hides it, so unsaved edits survive, but the tray's Quit ends the app with no prompt about a dirty document; the report window falls back to the browser's print dialog.
5. **A Desktop-only check sits in the shared module.** Windows.AskToClose skips the question when the window shows connect.html, the Desktop's chooser.
6. **Tests.** Two of the 305 fail in the full run and pass alone. The connection Details test (Ui.test.js, the Key box) is flaky under load: the typed key did not land before Save, so KeySet came back false. It then stops before deleting its connection, so the next test, which expects no connection on the server, finds three task buttons and fails too. The cleanup belongs in a finally so one flaky test does not take the next one down.
7. **Versions.** desktop/package.json says 0.5.0; the root, sidecar, client and server say 0.5.1.
8. **The Readme's Purpose** still says security is relaxed and a request with no token is the owner. That holds for a project's own server and the Sidecar; a Server refuses it.

### Dead code

- desktop/main.js requires fs and never uses it; overlay_for_theme is defined and never called (Windows.Options computes the overlay itself).
- public/js/stored.js: ServerKey reads window.ConsensusDesktop.Server.Url, a field no preload gives any more (the boot hands Roots); the page's-own-server scope (Read, Write or Remove with true as the scope) has no caller. Both are dead paths.
- sidecar/preload.js exposes an OpenRecent stub that answers an empty promise; the title bar only offers recent folders when the boot lists some, and Sidecar lists none.
- Exported but read nowhere outside their module: Windows.js WebPreferences, IsReportUrl, AskToClose, CLOSE_ANSWER_WAIT; Page.js DEFAULT_FOLDER (and Serve answers a Folder field nobody reads); Host.js Probe; License.js FromClaims; Instructions.js GUIDE_PATH; and the constants Clerk LEEWAY and WEBHOOK_WINDOW, Gate MODES, Participants DEFAULT_SCOPE, SERVICE_PATTERN and CLERK_FIELDS, Store HOME_FOLDER, PROJECTS_FOLDER, DEFAULT_PROJECT_NAME and CONTEXT_TITLE, Tasks DEFAULT_WRITES and DEFAULT_TASKS, Tools FILE_TOOLS, CONSENSUS_TOOLS, RUN_READS, RUN_WRITES and SHELL_OPERATORS, Ids CONTEXT, CORPUS and JOB, Roles ALLOWED, Users TYPES, View FIELDS, Llms NAME_PATTERN, Loop ANSWER_NUDGE, Mcp PROTOCOL_VERSIONS, ProjectPort VERSION and MODES, Files DEFAULT_LIMIT, bin/docs.js BUCKET, PAGE_PICTURES and Publish. Decided: the functions come off the export lists; the constants stay, since an export line documents a module's vocabulary and costs nothing.
- Read by the tests alone: desktop/Settings.js Apply, Default, HostEntry, DESKTOP_FIELDS and RECENT_LIMIT; desktop/Host.js HostPort; client/Settings.js Default, CleanName, UniqueName and NAME_LIMIT; sidecar/Settings.js Default and DefaultUser. They stay: a test is a reader.
- API operations the page never calls: report_markdown (agents and the guide use it) and copy_item (the tests and the docs alone; the tree's Copy goes through export). Both stay as API surface.
- Not dead, though absent from index.html: anchormap.js and live-preview.js are ES modules imported by codemirror-bundle.js.

### Duplicated code, and what to make of it

The four apps grew by copying. What each copy does, and how many there are:

| What | Where | Copies |
|---|---|---|
| The Electron switch filter and the argv slice (packaged or not) | desktop, sidecar, client, server main.js | 4 (the Server's regex adds one switch) |
| fail_to_start (console, error box, exit) | the four main.js | 4 variants |
| save_settings and the 300 ms save_settings_soon | desktop, sidecar, client | 3 |
| The bridge handlers boot, remember, theme, print-pdf, view-in-browser, quit, new-window | desktop, sidecar, client | 3, near verbatim |
| serve_page on the remembered page-port | desktop, client | 2 |
| window_options, create_window, Attach | desktop, sidecar, client | 3 |
| THEMES, DARK_THEMES, SCALES | desktop, sidecar and client Settings.js, and theme.js PALETTES | 4 definitions of one list |
| Settings Load, Write, Fill, Remember | the three Settings.js | 3; the two Remember differ (the Desktop's deep-copies and caps the key at 512, the Client's does neither) |
| The atomic temporary-file write | Host, License, Runs, Sidecar, Store, Users, the three Settings | 9 (Store's without the pid) |
| current_user, tier_now, set_license, clear_license | desktop/main.js, server/main.js | 2, verbatim |
| Trying a server with GET /api/me | desktop try_server, client try_server, Host.Probe, Projects.HostProjects | 4 fetch helpers with 4 answer shapes |
| The boot object and the ConsensusDesktop bridge | the three preloads and boot_info in three main.js | 3 of each, no shared definition of the fields (Sidecar fills Desktop's Host and Routed with nulls) |
| Connecting to a Server | Desktop's Hosts, chooser Servers section, connect_host_here; Client's Servers | 2 implementations |
| The two guides | .guides/build-with-consensus.md and build-with-sidecar.md | 54 lines in common |
| Two modules named Host | desktop/Host.js wraps src/Host.js | naming |

Proposed components, each a plain module with one job, following the Sidecar and Client pattern of handing in what differs:

- **electron/App.js**: the arguments (the switch filter, the slice, a parser given the app's own flags), fail_to_start, the common bridge handlers, the save-soon debounce and serve_page on a remembered port. An app hands it its title, its settings object, its boot fields and its extra handlers. Decided 2026-10-29: yes, electron/App.js and the base electron/Settings.js, Remember taking the Desktop's behaviour (a deep copy, the key capped) for every app.
- **electron/Settings.js**: the base of the three Settings modules: Path, Load, Write, Fill over a Default and a list of fields, Remember (one behaviour), and the look lists THEMES, DARK_THEMES, SCALES, which theme.js should also be the source of or read from (one list, served to the page).
- **src/Atomic.js**: WriteJson( path, value ) and WriteText( path, text ), temporary name with the pid, renamed into place, Store's rename retry included. Nine call sites become one.
- **electron/CurrentUser.js**: current_user, tier_now, set_license and clear_license over src/License.js, for the Desktop and the Server.
- **src/Probe.js** (or Host.Probe grown): one GET /api/me with a timeout, answering { Ok, SignIn, Version, Name, Me, Error }, used by the Desktop, the Client, Host.Status and Projects.HostProjects.
- **The Server app on electron/Windows.js**: Options, Attach, AttachChrome, PrintToPdf and ViewInBrowser as the other three, its tray and gate kept. Decided 2026-10-29: yes.
- **Windows.BuildMenu** takes the items it is given, so the Client leaves Open folder out.

Decided without a thread: Operations.js stays one module (3527 lines, one definition per operation, eighteen marked sections; splitting it buys nothing the sections do not already give). The two guides stay two files: the Sidecar's is deliberately shorter, and the shared This server section is already composed by Instructions.Make.
