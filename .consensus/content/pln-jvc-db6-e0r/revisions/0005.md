# Teams

Consensus for more than one person. Four plans were found on 2026-10-18 (LLM Tasks was Usage Scenarios then) to be answering one question from different angles: who is acting on a server, where from, on whose behalf, and what follows from the answer for the product and for what is sold. This plan is their master: it states the question and the model once, names each part and what it owns, and gives the order. The parts are its subplans; nothing is built from this page itself. The name, the place of Promotion and Monetization inside it and the order were settled on 2026-10-18 (the decisions thread, resolved with no reply).


## The question

A server on one machine with one owner needs no answer: a request is the owner, and the owner's agent session is the owner's delegate. The moment a server listens for others, three things have to be known about every request: the person behind it, what that person may do in the project at hand, and, when an LLM made it, which person it acted for. The Free tier never asks the question; the Team and hosted tiers cannot ship without it, and Promotion and Monetization says nothing is sold until it is answered.


## The model

Settled in the chat of 2026-10-18 and written out in User Management, The model:

- A person is the only principal. Clerk identifies people, once; Consensus manages roles and permissions, per project, in the role folders. Consensus keeps no passwords and no sign-in of its own.
- An LLM is never a user. A server LLM connection runs as the person who pressed the button; an agent session acts as the person whose token it holds.
- Scope decides whether identity is checked: Local trusts the machine; Public authenticates with Clerk; Public without Clerk is a trusted network where every request is the owner.
- A token is the one credential for anything that is not a browser: a person's, named, good until revoked.


## The parts

- **User Management** owns the model, the registry (Users.json, keyed by Clerk id, no credentials), the role folders (Owners, Members, Watchers), the Users folder and user pages, a person's tokens, runs as the presser, the Admin, and the migration away from the participants in consensus.json. Five steps; Steps 1 and 2 first.
- **Clerk**, its subplan, owns the sign-in: the Clerk application and its dashboard choices, the session JWT the server verifies, the ClerkJS page, the webhook that fills the registry, the production instance under consensus-ai.liquicode.com. Its Step 1 is the dashboard alone; Steps 2 to 5 are User Management's Step 4.
- **LLM Tasks** owns how an LLM takes part once identity is settled: the LLM tasks as records the owner edits (a name, a package, a writes level that is the permission, a prompt), the default set (Answer, Enhance, Work, Explain, Session), the Work options for git sync and auto-commit, Explain (the read-only conversation with the project, the one task a Watcher has), and the ways-of-working guide page. It assumes a run is the presser's.
- **Promotion and Monetization** owns what is free and what is sold, and the order of revenue. Its Steps 1 to 4 (ready to be seen, distribution, launch, the desktop license and run quota) need none of the above and start now; Steps 5 and 6 (the Team image, the hosted service) wait on User Management and Clerk.


## The order

1. Promotion and Monetization Steps 1 to 3, alongside everything below.
2. User Management Steps 1 and 2: the trusted-network wording, the participants and connection tokens out of consensus.json, runs as the presser. Nothing a single user sees changes.
3. LLM Tasks: the tasks as records, then Enhance and the Work options, which make the single-user loop better before any team exists; Explain, which is what a Watcher is for; the guide page with them.
4. Promotion and Monetization Step 4: the desktop license and the run quota, the first money.
5. User Management Step 3 and Clerk Steps 1 to 5: users, roles, sign-in, the production instance.
6. User Management Step 5, then Promotion and Monetization Steps 5 and 6: the Team image, then hosting.


## What stays out

- The Installer plan: signing and auto-update are their own line and gate the desktop license only.
- Workspace Files, Workflows and Plugins: unrelated to who is calling.
