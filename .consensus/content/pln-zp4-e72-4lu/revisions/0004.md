# Sidecar Edition

We are going to simplify things greatly.

We are going to rebrand Desktop as Sidecar and remove all server and multiuser functionality.
This app opens only a local project folder and never connects to a Server.
This app never asks for a user sign-in.
This app is used only in sidecar mode.

This app's settings are stored in `sidecar.json` file.
Settings includes all view options, view state, user name, etc. that it does today.


## What Sidecar is

- One Electron application, Consensus Sidecar. A window holds one project: a local folder, its `.consensus` made when missing. With no folder the window shows the chooser: the recent folders, Open folder and New project. Another folder is another window, as today.
- The window's server is the sidecar over that folder (`src/Sidecar.js`, unchanged): it listens on 127.0.0.1 alone, its port hashed from the folder into 3600 to 3699, its address in `<folder>/.consensus/~sidecar.json` while the project is open; a second launch on a folder already open brings that window to the front.
- One person uses it: the user named in `sidecar.json`, the owner of every project opened. There is no sign-in, no account, no token and no tier. Sidecar is free: it reads no license.
- An LLM session works beside it through the API or MCP (`consensus mcp <folder>`), saying who it is with `X-Consensus-Service`; what it posts reads "<service> by <user name>". A request with no token is the user; a request carrying a token is refused.
- The consensus rules stay as they are for one person: a thread is resolved by the user, applied by the user or the LLM, and waits on the user and the LLM.


## Settings: sidecar.json

- The file is `<config>/sidecar.json`, the config folder being `~/.consensus` (`--config <folder>` for another, as the smokes use). Sidecar reads and writes this file and no other of the config folder.
- Its fields:
  - `User`: `{ Name, Display }`, the person; `{ "Name": "user", "Display": "User" }` by default.
  - `States`: the plan states the tree offers (today in consensus.json).
  - `Recent`: the project folders opened, newest first (limit 20).
  - `Theme` and `Scale`: the look, as today (the ten palettes; small, normal, large).
  - `Remembered`: the page's view state by key (the open item, the folds, the tabs, the sort, the hidden panes, the widths), as today.
- The address file `<folder>/.consensus/~sidecar.json` is another file, in the project folder, and is unchanged.
- A project's own settings stay in its `.consensus/project.json`; fields of the Server's (Roles, Llm, Tasks) found there are ignored.


## What goes

- Connect to Server: the Hosts, `--connect`, the Server routing of Open folder (`desktop/Host.js`), `Projects.HostProjects`, the server rows of the chooser.
- Sign-in and licensing: `src/License.js`, `src/Clerk.js`, `user.json`, the tiers, the sign-in box, the license line of About.
- Multiuser: users, accounts, roles (Owners, Members, Service accounts, Watchers), the Users page, minted tokens and the "LLM session" token of the LLM Instructions; `src/Users.js`, `src/Roles.js`, `src/Gate.js` as far as they serve them.
- consensus.json, desktop.json and user.json are no longer read.


## What stays

- Plans, documents, folders, threads, revisions, anchors, the rules, reports and Print to PDF, the editor and the View, the look controls, the project tree, the waiting list, the project settings.
- The API, the MCP (`POST /api/mcp` and `bin/mcp.js`), and the instructions page, rewritten for sidecar mode alone.


## Steps

1. **sidecar.json and the user.** `desktop/Settings.js` writes `sidecar.json` with the fields above; the sidecar takes its user and its States from it in place of consensus.json; tests.
2. **The app loses the Server.** Connect to Server, the Hosts, the Server routing, sign-in, licensing and the tiers leave the app and the page.
3. **The server code loses multiuser.** Users, roles, tokens and Clerk leave `src/`; every request is the user; the instructions page loses its token and Server sections; tests.
4. **The rename.** The product name, the installer, the window titles, About, the usage lines.
5. **The guide.** The user guide, the features page, the Readme and the smoke, for Sidecar.
