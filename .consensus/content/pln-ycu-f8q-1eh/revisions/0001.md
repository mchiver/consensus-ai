# Agent Instructions

Consensus serves the instructions an agent session needs to work with it at one plain link, so any session on this machine, in any repo, can be told: "read the instructions at http://127.0.0.1:3500/instructions".

## The link

- `GET /instructions` serves the instructions as plain text (`text/plain; charset=utf-8`), readable as is by `curl` and by a person in the browser. No token is needed: like the rest of the server, it answers on 127.0.0.1 only.
- The text is `.guides/build-with-consensus.md` (the one source; it stays in the repo), with a short **This server** section put first by the server when it answers:
  - the API's address (`http://127.0.0.1:<Port>/api`);
  - the settings file's full path, where the session reads the `llm` participant's token (the token itself is never served);
  - the data folder's full path, which the session never edits.
- The owner's line to a new session: "read the instructions at http://127.0.0.1:3500/instructions" (with `curl`: a session's web fetch tool may not reach 127.0.0.1; the guide says so in its first line).

## What the guide gains

The guide today covers the API, "your turn" and the build loop. It gains what the owner and the agent have settled in practice:

- **Finding your project.** List the projects (`GET /api/projects`); the one named after your repo (or holding a corpus of it) is yours. If none or more than one fits, ask the owner, and remember the answer for the session.
- **Loading your context** ("load your context"): read the project's context and its tree of plans with their states, and what waits on you; report it in a few lines.
- **What the owner's words mean:**
  - "check consensus", "check again": report what changed and what waits on you, and act on nothing.
  - "your turn": act as the llm participant on everything waiting on you.
  - "build it", "implement it": the build loop, for the plan named or just discussed.
  - A message holding any question is answered only; its instructions wait for a message with no question.
- **Drafting a plan:** decided defaults go into the text as statements; threads only for real questions. A request to rework a document is answered with a reply holding the exact new text, applied once the owner resolves it.
- **Long builds:** stop at natural checkpoints (server done, page done, tests passing, build log posted) with a short "done so far / next" note, and wait for "continue".
- **Commits:** in your own repo, titled after the plan, no attribution trailers.
- **The servers:** never start, stop or restart Consensus or a context server unless the owner says so; check the ports first. When asked: start each as its own hidden process with output in the repo's `~logs`, the context server first.
- **Calling the API:** small scripts that read the token from the settings file and never print it. On Windows, pass API paths to scripts without a leading `/` (Git Bash rewrites `/api/...` into a file path).

## Checks

An API test: `GET /instructions` answers 200 as plain text, starts with the This server section (the port and the settings path of the running server), holds the guide's text, and holds no token.
