# UI Tweaks V

- The current thread can be selected by clicking on anchored text. The threads pane lists the threads the filter matches plus the selected thread, at its place in the text order: the selected thread stays listed whatever the filter, until another thread is picked or the selection is cleared.

- When selecting text, a popup is shown allowing "Comment" and "New Subplan" commands. A "Copy" command is also available: it puts the selected text on the clipboard as it reads (plain text) and clears the selection. Copy is offered on documents too, where Comment and New Subplan are not.

- The plan state called "Proposal" is renamed to "Draft". The default plan states are "Draft", "Plan", "Working" and "Finished". A server whose settings list "Proposal" and not "Draft" renames it once at startup, in the settings and in every plan in that state. The "New Draft" commands in the menus below are labelled "New " + the first configured state, so with the defaults they read "New Draft". The docs (the guide's settings and projects pages, the readme) follow.

- The connected server is displayed plainly in the little connection panel next to the Settings button: its address without the scheme (cube4:3500, for example), with the connection's name and the server's version in the tooltip. Live or offline stays as the panel's color and in the tooltip.

- The view state of the Project Tree for a specific server is remembered between sessions: the current project, the open/closed folders, the open tabs and the active one, the sort order and the show-updated flag, kept under the connected server's address. The look is shared by every server: pane widths, hidden panes, highlight and scale. A remembered tab whose item is gone from the server is dropped silently at load. The theme: the connect screen's picker sets the desktop's default theme; the page's picker sets the theme of the connected server, kept with that server's view state; a server with none uses the default.

- The show/hide threads button should appear like the show/hide projects button: a small icon in the right side of the tab area.

- Copy, Paste and Export work on the json an export produces, for projects, folders, plans and documents alike:
    - Copy puts the item's export json on the system clipboard, so it can be pasted into another project, into the app connected to another server, or into a file.
    - Paste reads the clipboard: export json is imported into the target (a project's root or a folder), every id new. A project's json pastes as a folder named after the project, holding its items.
    - Ctrl+C and Ctrl+V on the tree do the same as Copy and Paste.
    - The in-page clipboard of today ({ Id, Name } and a server-side copy) goes away.
    - Export shows the item's json in the export popup, to copy or download, as a project's export does today. A folder's or an item's export is the project file format with that item as its content, so the existing import takes it as a project too.
    - The API gains the export of a folder or an item, and the import of a file into a project's root or a folder.
    - One use: a Template project, on any server, whose items are copied into new projects.
