# User Management

A discussion starter: what the server knows about who is who today, what user management would add, a proposed shape to argue with, and the open questions as threads. Nothing below is decided until its thread is.


## Today

- The participants live in consensus.json, edited in the Settings popup: each has a Name (what threads and revisions record), a Display, a Role (owner, llm or member) and an optional Token. Only the owner resolves threads and writes the settings; only the llm applies; everyone else takes part.
- A request is identified by its token (Authorization: Bearer). A request with no token is the owner: security is relaxed, so the browser signs nothing and the desktop connects as the owner. The llm participant's token is served to whoever reads /instructions.
- cube4 listens beyond the machine: anyone who can reach it acts as the owner. The Readme names an Owner Token as not yet a plan; this plan takes its place.


## What user management means here

People besides the owner working on the same server, each as themselves: signed in, named in what they write, allowed what their role allows. Not accounts in the sense of a public site: there is no self-registration, no password reset by mail; the owner makes the users.


## A proposed shape, to argue with

- **Sign-in by token.** Each participant keeps a Token, as today; signing in is giving it. The browser page gets a sign-in box (shown when the API answers 401), keeps the token in its storage per server, and sends it with every request; a Sign out forgets it. The desktop keeps a token per saved server (an optional field beside the Url), sends it with what it forwards, and says on the connect screen who the server takes it for.
- **Anonymous requests are a setting.** `Anonymous` in consensus.json: `owner` (today's behaviour: a request with no token is the owner; right for a server on 127.0.0.1) or `none` (a request with no token is refused with 401; right for a server that listens beyond the machine). The default is `owner` when Host is 127.0.0.1 and `none` otherwise, and the Settings popup shows it with a warning when a server beyond the machine is left open.
- **Several owners.** Role owner on more than one participant; wherever a rule says "the owner", any owner will do. The roles stay the three: owner, llm, member.
- **The instructions page** requires an owner's or the llm's token when Anonymous is `none`, since it serves the llm's token.
- **Users are made in the Settings popup**, as participants are today: the owner adds one, gives it a Display and a Role, makes its token with New and hands it over by Copy. A participant whose token changes is signed out everywhere.
- **Nothing per project.** Rights are server-wide; a member sees every project. Per-project rights are a later plan if they are ever needed.


## Out of scope

- Passwords and sessions (cookies, hashing, expiry): a token is the credential, as it is for the llm and was for the workers.
- Self-registration, invitations by mail, password reset.
- An audit log beyond what threads and revisions already record (By and At on everything).
