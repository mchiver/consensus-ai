# Step 2: The shared Electron scaffold

The copies between desktop, sidecar and client main.js and their Settings modules become shared modules, each handed what differs. The apps keep only their own: their arguments, their boot fields, their own handlers.

## The modules

- **electron/App.js**
  - Arguments( argv, { Flags, Positional, Rest } ) answers { Options, Positional, Rest }: the Electron switches filtered out, the slice after the executable (packaged or from the checkout); Flags a list of { Name: '--port', Takes: 'value' | 'number' | 'flag', Key: 'Port' }, each landing in Options by its Key (null or false when absent), a value flag throwing when nothing or another flag follows it, 'number' also checking a whole positive number; Positional true allows one bare argument (the folder), else a bare argument throws; Rest true keeps the arguments the Flags do not name, in order, for src/Start.js (the Desktop and the Server), Rest false throwing on an unknown argument (the Sidecar and the Client). A folder is a value the app resolves itself. What is thrown is the message the app prints with its usage.
  - FailToStart( Title, Message, Quiet ): the console, the error box unless Quiet, exit 1.
  - Saver( Write ): { Save(), SaveSoon() } over a 300 ms debounce, Save flushing a pending SaveSoon; the window-all-closed flush in one place.
  - AttachHandlers( Fields ): the common bridge handlers boot, remember, theme, print-pdf, view-in-browser, quit and new-window, over Fields = { Boot(), Settings, Saver, Roots(), NewWindow(), Themes } plus WINDOWS.AttachChrome(); an app adds its own handlers after.
  - ServePage( Settings, Saver, Options ): the page server on the remembered page-port, a free one remembered instead.
- **electron/Settings.js**, the base of the three: Make( { File, Default(), Fill( given, settings ) } ) answers { Path( Folder ), Load( Folder ), Write( Folder, Settings ), Remember( Settings, Key, Value ) }, with one Remember (a deep copy of the value, the key capped at 512 characters, null or undefined forgetting), the atomic write from src/Atomic.js, and the look lists THEMES, DARK_THEMES and SCALES defined here once. Each app's Settings keeps its Default, its Fill of its own fields and its own functions (the Desktop's Recent and Hosts, the Client's Servers, the Sidecar's User).
- **src/Atomic.js**: WriteText( Path, Text ) and WriteJson( Path, Value ): the folder made, a temporary file named with the pid, renamed into place with Store's rename retry (Windows holds a file a reader has open for a moment). The nine writes (Host, License, Runs, Sidecar, Store, Users and the three Settings) call it.
- **electron/CurrentUser.js**: CurrentUser( Config ) over src/License.js: Read() (a lapsed record removed and logged), Tier() (the tier object the pages take), SetLicense( Token, Settings ) and Clear(). desktop/main.js and server/main.js use it in place of their copies.
- **src/Probe.js**: Probe( Url, { Token?, Timeout? } ) is one GET /api/me: { Ok, SignIn, Closed, Version, Name, Me, Participants, States, Url, Error }. Host.Status, the Desktop's and the Client's try_server and Projects.HostProjects use it for the address check; HostProjects keeps its own GET /api/projects after.
- **electron/Servers.js**: the Servers store taken out of client/Settings.js (CleanName, CleanUrl, UniqueName, AddServer, RenameServer, RemoveServer, named), used by the Client now and by the Desktop after Step 5.

## The look lists

theme.js is a browser script and the Settings modules run in Node, so one cannot require the other. The list lives in electron/Settings.js, and a test reads theme.js's PALETTES and asserts the two agree, so a palette added to the page cannot be refused by an app.

## Checked by

New tests: Atomic (a write lands whole, the temporary file is gone, two processes' names differ), Probe (a Server, a sign-in, a closed gate, no answer), App.Arguments (each app's command line), the look lists agree. The existing Desktop, Sidecar, Client and ServerApp tests pass unchanged in what they assert.
