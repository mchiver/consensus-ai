# Step 3: Local LLMs and Workspaces

Subplan of Consensus Desktop. LLM connections and workspaces are reintroduced in the desktop application; users add them within a project's `Context` folder. A sketch, to be detailed once Step 2 is in use.

## The sketch

- LLM connections (claude-cli, ollama) and workspaces (a local folder, with Include and Exclude) are the desktop's, kept in `desktop.json` per server and project, never in the server's data. The Context folder of a project shows them, in the desktop only, as items of its own kind beside the documents: each opens to its settings.
- An LLM connection names the participant the LLM posts as (the llm participant by default). No tokens are involved; user management is a later plan of its own.
- The desktop takes the LLM's turn with the local model and the local files: it reads what waits on that participant from the server, runs the model with the workspace's files and the Context folder's documents at hand (the tool loop and the file tools come back from the worker's code), and posts the replies and applies through the server's API as that participant. Review returns as a button in the desktop, not in the server's page.
- Builds (implementing a plan in a workspace) and git are decided when this Subplan is detailed.
