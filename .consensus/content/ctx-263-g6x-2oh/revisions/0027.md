# Consensus

## Purpose

A web app where a person (the owner) and an LLM work a proposal through, thread by thread, until every thread is resolved and applied and the proposal becomes a plan. Plain files. Since plan Consensus Desktop, Step 1 (2026-10-01), the server calls no LLM and reads no code: every LLM takes part through the API as the llm participant, from wherever it runs (today: the agent session, on "your turn in Consensus"). Security is relaxed for now: a request with no token is the owner (accepted on cube4's private network; an Owner Token plan is for later).

## Architecture and where things live

- Node + Express, AngularJS + Bootstrap, Monaco. No TypeScript; few dependencies (express, angular, bootstrap, marked, monaco-editor).
- `bin/consensus.js` starts it; `src/Server.js` start-up; `src/Api.js` every route and rule; `src/Rules.js` the consensus rules; `src/Store.js` the data folder and the Step 1 migration; `src/Tree.js` trees and the Context folder's rules; `src/Participants.js` identity, the States and the settings' checks; `src/Anchors.js` anchors; `src/ProjectPort.js` export and import; `src/Ids.js` ids.
- Removed in Step 1 (git history keeps them; Step 3 draws on them): the LLM callers and prompts (Llm.js), search and indexing (Index.js, Vectors.js), corpora (Corpus.js, Zip.js, Filter.js), the workers (Workers.js, Worker.js, Workspace.js, Mcp.js, bin/worker.js, public/worker/) and the worker app (worker-app/).
- `public/index.html`, `public/js/*.js` (one file per pane or feature; `settings.js` the settings popup), `public/css/consensus.css`.
- `.guides/build-with-consensus.md`: how an agent session works here; served at `GET /instructions` with the server's address and llm token first.
- Tests: `node --test` (118 after Step 2); `test/Ui.test.js` drives headless Chrome or Edge; `test/Desktop.test.js` the desktop's modules with the real server.
- Deployment (plan Docker Image): `Dockerfile`, `.dockerignore`, `compose.yaml`. The live server is cube4, `http://cube4:3500` (compose in `~/consensus/`, volume `consensus-data`); no registry: built on the dev machine, sent by `docker save | ssh claude@cube4 docker load`. Port published on IPv4 only (Chrome's Private Network Access blocked the page over cube4's global IPv6). The agent session works there over the API with cube4's llm token. cube4 runs the Step 1 build since 2026-10-01; its data was migrated at that start.

## Data (the data folder, never in git)

- `consensus.json` (Port, Host, States, Participants); `projects.json` (names, order); `projects/<id>/project.json` (tree, Context and ContextFolder ids); `proposals/<id>/` (proposal.json, proposal.md, threads.json, revisions/); `trash/`.
- Proposal kinds: plan (threads, state), document (neither). A project's Readme is a document titled Readme in its Context folder (Step 1 retired the kind context; an old one keeps its ctx- id; the start after the Readme commit of 2026-10-01 renamed those still titled Context).
- Ids (plan Global Ids): `<kind>-xxx-xxx-xxx`, kinds `prj pln doc ctx fld cor thr rep rev run job`, base36 from the crypto source; Default is `default`. Revisions have `Id` and `Parent`, proposals a `Head`, Applied records a `RevisionId`; a revision number is only the sequence on one server.

## Conventions (CLAUDE.md)

- Tabs; spaces inside brackets; braces on new lines; no arrow functions; async/await.
- UPPER_CASE constants, lower_case locals and functions, PascalCase parameters and exports; never camelCase. Descriptive names; separator lines between blocks.
- `~` folders stay out of git. Commits carry no attribution trailers.

## Settled decisions

- Threads: contested, then resolved (owner only: Reply and resolve, Resolve accepting the LLM's last outcome or recommendation, or Comment and resolve), then applied by the LLM as a new revision. A reply reopens a resolved thread. The owner may delete any thread.
- Plan states (Proposal, Plan, Working, Finished) come from settings; anyone sets them; they never depend on threads.
- Projects hold trees of folders, plans, documents and corpora. Subplans: a plan holds plans only, organizational, no rules between states; a Subplan's prompt carries its parent plans as text (plan Plans and Subplans).
- Every project has a Context folder, first in its tree, holding its Readme (this document) and any other document: documents only, flat, and documents nowhere else; neither the folder nor the Readme is renamed, moved, copied or deleted. The agent session keeps the Readme up to date (an edit through the API); it is read by everyone who works on the project.
- All LLMs are the `llm` participant, through the API: the server calls none (Step 1). The agent session (Claude Code) replies, applies, drafts plans, keeps the Readme and implements plans when asked. Review, Build, search, corpora and workers were removed from the server in Step 1; local LLMs and workspaces return in the desktop (Step 3).
- Settings (Step 1): the owner edits consensus.json in the page's Settings popup, saved whole through PUT /api/settings and checked as at start; Host and Port take effect at the next start. Theme and scale stay in the browser's storage.
- Build loop (agent session): a plan with every thread applied is built on the owner's word; the agent sets it Working, implements only what it says, tests, and posts a contested build log naming its model. Resolving accepts: apply it, commit (titled after the plan), set Finished, update this Readme. A reply sends it back.
- No automated git: workers and builds never branch, commit or push on their own; git is the owner's, outside Consensus or with Commit and Push on the worker's page. A git workflow is a later plan.
- Consensus Desktop (plan, three Subplans built in order): Step 1 (done 2026-10-01) stripped the server to the core; Step 2 (done 2026-10-01) is the Electron desktop client, `desktop/` (`npm run desktop`, run from the checkout): a connect screen (saved servers, tried before they are saved; one local Consensus server started in the app's process over a data folder), then the desktop's own copy of the page (`desktop/page/`, the server's Web UI being frozen after Step 1), served from the app's own origin on 127.0.0.1, which forwards /api and /instructions to the connected server (the server sends no CORS headers, and Electron 44 runs no preload with web security off, so the base URL client.js reads stays the page's own origin); desktop.json in `%APPDATA%/consensus-desktop/` holds Servers, Local, Last, Theme and Scale; New window is a second instance; `/api/me` says the server's Version. After Step 2 (2026-10-01) the Context document was renamed Readme (thread on Step 2): the page says "Readme of <project>" in `public/` and in the desktop's copy alike, the one named exception to the freeze. Step 3 (plan detailed 2026-10-01, not yet built) brings LLM connections and workspaces back in the desktop, kept in desktop.json and shown in every project's Context folder (a connection once per desktop; a workspace, a path to a folder, with its project), each in a tab with a form, buttons and a log: Review, Build and Session package the checked context items (instructions, Readme, document list, waiting threads) with an editable prompt and run a claude-cli one-shot in the workspace's folder, the model working the API itself as the llm participant with the token from /instructions; one run at a time, logged in runs/<id>.json; ollama and its tool loop are Step 4. Corpora, workers and the worker app (plans Workers, Review, Build, Worker Electron App) are retired with Step 1.
- Export and import (plan Project Import and Export): a whole project as one json object, API first (owner or llm token), never tokens. A project not here comes in with ids intact; one here is imported as a copy ("Copy of <name> (imported <date>)", every id new) or merged (revisions by Id; a conflict gets a merge revision with the newer text; nothing removed). Since Step 1 the export carries the Context folder and no corpora or workers; an older export still imports, those parts dropped.
- UI (plans UI Tweaks, II, III, Tabs): VS Code style tree with one actions menu per row; tabs per item, detachable into windows; light/dark and small/normal/large.

## Glossary

- **Proposal**: any text item with revisions; a **plan** is the kind with threads and a state.
- **Thread**: a comment on a passage (anchored) or the whole document. **Apply**: the LLM puts a resolved thread's outcome into the text.
- **Context folder**: a project's first folder, documents only; **Readme**: this document, the project's background (titled Context before 2026-10-01).
