# Consensus

## Purpose

A web app where a person (the owner) and an LLM work a proposal through, thread by thread, until every thread is resolved and applied and the proposal becomes a plan. Plain files. Since plan Consensus Desktop, Step 1 (2026-10-01), the server calls no LLM and reads no code: every LLM takes part through the API as an llm participant, from wherever it runs (the agent session, on "your turn in Consensus"; since Run Shapes Step 3 the server's own LLM connections too, each a participant of its own, run in a project's folder on the server's machine). The desktop shows several servers at once, each a root of its tree (Run Shapes Step 5). Security is relaxed for now: a request with no token is the owner (accepted on cube4's private network; an Owner Token plan is for later).

Every project has a prj- id (the id default is gone). - Proposal kinds: plan (threads, state), document (neither). A project's Readme is a document titled Readme in its Context folder (Step 1 retired the kind context; an old one keeps its ctx- id; the start after the Readme commit of 2026-10-01 renamed those still titled Context).

## Conventions (CLAUDE.md)

- Tabs; spaces inside brackets; braces on new lines; no arrow functions; async/await.

## Settled decisions

- Threads: contested, then resolved (owner only: Reply and resolve, Resolve accepting the LLM's last outcome or recommendation, or Comment and resolve), then applied by the LLM as a new revision. A reply reopens a resolved thread. The owner may delete any thread.
- Plan states (Draft, Plan, Working, Finished; the first was Proposal before UI Tweaks V, renamed once at start where the list still had it) come from settings; anyone sets them; they never depend on threads. The tree's "New Draft" is named after the first state.
- Projects hold trees of folders, plans, documents and corpora. Subplans: a plan holds plans only, organizational, no rules between states; a Subplan's prompt carries its parent plans as text (plan Plans and Subplans).
- Every project has a Context folder, first in its tree, holding its Readme (this document) and any other document: documents only, flat, and documents nowhere else; neither the folder nor the Readme is renamed, moved, copied or deleted. The agent session keeps the Readme up to date (an edit through the API); it is read by everyone who works on the project.
- Every LLM takes part through the API as an llm participant: the hand-made `llm` for the agent session (Claude Code replies, applies, drafts plans, keeps the Readme and implements plans when asked), and since Run Shapes Step 3 (2026-10-12) one per LLM connection of the settings, named `<connection>@<server name>`, with a token the server makes and keeps on the connection. A run (Review, Build, Session) is started by any participant but an llm one, works in the project's folder on the server's machine, one per connection at a time, its record with who asked in `<config>/runs/`. Review, Build, search, corpora and workers were removed from the server in Consensus Desktop Step 1; local LLMs and workspaces returned in the desktop (its Step 3) and the runs moved into the server with Run Shapes Step 3.
- Settings (Step 1): the owner edits consensus.json in the page's Settings popup, saved through PUT /api/settings and checked as at start; since Run Shapes the popup shows Name, Scope and Port, the route writes those five fields and keeps the desktop's, and Scope and Port take effect at the next start. Theme and scale stay in the browser's storage; in the desktop, the default theme and a theme per server are in the config (desktop.json before Run Shapes; UI Tweaks V).
- Build loop (agent session): a plan with every thread applied is built on the owner's word; the agent sets it Working, implements only what it says, tests, and posts a contested build log naming its model. Resolving accepts: apply it, commit (titled after the plan), set Finished, update this Readme. A reply sends it back.

## Glossary

- **Proposal**: any text item with revisions; a **plan** is the kind with threads and a state.
- **Thread**: a comment on a passage (anchored) or the whole document. **Apply**: the LLM puts a resolved thread's outcome into the text.
- **Context folder**: a project's first folder, documents only; **Readme**: this document, the project's background (titled Context before 2026-10-01).
