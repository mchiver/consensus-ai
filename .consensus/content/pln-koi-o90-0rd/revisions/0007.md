# Markdown Editor

Replace the 2-pane editor/viewer with a single Markdown Editor.
Model the markdown editor after that which is found in Obsidian.
After this is in place, we will no longer need the Read/Edit buttons and modes.
The Save button will become more important as that will tell consensus when to commit edits and establish Revisions.
This will complicate things because Consensus must now retain edits when the user switches tabs and prompt for saving on application shutdown.

The draft above is the owner's (2026-10-16); it was reviewed in eight threads, set aside for plan UI Components, and comes back here (2026-10-17) with what that plan put in place. The sections below are the LLM's proposal from that review, each point to be decided on its thread before the build.

## What is already there

- CodeMirror 6 is in the page (plan UI Components, Step 3): the core packages served from `/vendor/codemirror/<package>/` through an import map, no build step, a palette-built theme and highlight style, and the Editor setting (Monaco or CodeMirror) behind the title bar's gear. The Edit view, the comment box and the reply box open the engine the setting names.
- The threads' passages are already marked in the CodeMirror editor by state, honouring the Highlight picker: `public/js/anchormap.js` maps the server's plain-text anchor positions onto source offsets through the Lezer tree (tested against `src/Anchors.js` over the guide and the project's texts), the marks follow the text through edits, a click on a mark selects its thread, and Save has the server find the anchors again.
- An unsaved edit is kept with its tab (the text and the revision it was made from) in the remembered state, so it survives a tab switch and a restart, and comes back as stale when the plan moved on. Save carries the revision it was made from and a stale save is refused; the Stale banner offers Discard.
- The page is components (plan UI Components): document-editor holds editor-header, html-view (Read), edit-view (the editor beside its preview) and revisions-view; the tab bar and the Tabs service hold the drafts; the title bar is the window's in the desktop.

## The proposal

1. The view. Obsidian shows a note three ways: Source mode (plain markdown), Live Preview (rendered in place, the syntax shown only on the cursor's line) and Reading view (rendered, not editable). Decided (2026-10-17): with the Editor setting on CodeMirror, Live Preview is the one view of a plan or document, and a Source toggle in the heading switches it to plain markdown, as Obsidian's does; Reading view goes from that mode. With the setting on Monaco the page keeps today's shape (point 2).
2. The engine. A Live Preview is CodeMirror decorations: syntax characters hidden on every line but the cursor's, headings and emphasis styled, some constructs replaced by widgets. Decided (2026-10-17): CodeMirror is the Live Preview's engine. Monaco stays, with the Editor setting, as the backup until the CodeMirror editor has proven itself: with the setting on Monaco the page works as it does today (the Read view, the Edit view with Monaco beside its preview, Save as now), and nothing of Monaco or of those views is removed in this plan. Their removal, with the setting's, is a plan of its own once the owner is sure.
3. What renders in place in the first cut. Decided (2026-10-17): headings, emphasis, inline code, links (shown as their text, the URL on the cursor's line), bullet and numbered lists, task checkboxes, blockquotes, fenced code blocks and horizontal rules, and tables and images with them: an image shows under its line as a widget, the line's source coming back when the cursor is on it; a table is rendered as a block widget while the cursor is outside it and shown as source while the cursor is inside it, the way the fenced code blocks are handled, so both ride on the mechanism the first cut has anyway. Editing a table in its rendered grid, as Obsidian allows, is not in this plan.
4. The threads in the editor. Everything the Read view does moves into the CodeMirror editor (the Read view keeps it for Monaco mode): the passages highlighted (done), a click selecting the thread and scrolling its card into view (done), the thread card scrolling the editor to its passage, selecting text offering Copy, Comment and Start a new Subplan (or Re-anchor here), and a search hit or a waiting item flashing its passage. Anchors stay the server's, found in the rendered plain text; the anchor map stays the bridge, and a thread whose plain text disagrees is listed without a highlight, as now.
5. The heading. Decided (2026-10-17): Read and Edit stay, shown only while the Editor setting is Monaco; in CodeMirror mode the Source toggle stands in their place. Revisions stays as it is, the text at a revision shown in the editor read-only; an archived plan opens read-only too, in the one editor. A document (the Readme, the LLM instructions) opens in the same editor, without threads. Save stays as a button, disabled when the text is clean; a dot on the tab's label while it is dirty, so an unsaved tab shows in the strip.
6. Revisions and the live text. Typing never makes a revision; Save (Ctrl+S) does, one revision per save. Because in CodeMirror mode the editor is always open, a new revision arriving while the text is on screen (a thread applied, a save elsewhere) is the common case: with no unsaved edit the editor takes the new text silently, keeping the cursor and the scroll; with an unsaved edit, the Stale banner as today, with Discard. No merge of two texts in this plan.
7. Closing with a draft. Closing a tab that holds a draft (Close, the tab's ×) asks Save / Discard / Cancel. Decided (2026-10-17): Close others and Close all ask the same when any tab they would close is dirty, the one prompt listing the documents that would lose their changes, one per line; Save saves them all and closes, Discard closes them unsaved, Cancel closes nothing. A detached window's close counts as the tab's.
8. Shutdown. The desktop's window close asks the page, over the preload, whether any tab is dirty, and then shows Save all / Don't save / Cancel; a browser raises its own leave-page prompt from beforeunload when a dirty tab exists; a headless server cannot prompt anyone. Drafts persist across a restart in every case, so Don't save loses nothing: the dirty tabs come back dirty.
9. Hotkeys. Ctrl+E ("Edit; from Edit, save and read") becomes the Source toggle, as in Obsidian; Ctrl+S stays Save; Ctrl+Shift+C (comment on the whole document) stays. The Hotkeys popup and the guide change with them.
10. Out of scope unless the owner says otherwise: Obsidian's other features (wiki links, backlinks, the outline, editing a table in its rendered grid), the removal of Monaco, and any change to how the LLM reads and writes text, which goes over the API and does not see the editor.

## The build

Each step a commit, designed on its line (or its subplan) before its build, as plan UI Components was done.

1. Live Preview: the decorations that render the markdown in place in the CodeMirror editor, with the Source toggle; the preview pane goes from the Edit view.
2. The threads in the editor: the thread card scrolling to its passage, the selection buttons (Copy, Comment, Start a new Subplan, Re-anchor here), the flash from a search hit or a waiting item.
3. One view: in CodeMirror mode Read and Edit give way to the Source toggle, Revisions beside the editor, read-only for archived plans and old revisions, the live revision taken silently when clean, the dirty dot on tabs, the hotkeys; Monaco mode keeps today's Read and Edit behind the Editor setting.
4. Closing and shutdown: the Save / Discard / Cancel prompts on a tab's close, the desktop's close prompt over the preload, the browser's beforeunload.
5. The guide, its pictures, the help, the smoke.

Tests: the server's node tests keep passing untouched; the browser tests follow the views they drive; the smoke (`npm run smoke`) at the end of each step.
