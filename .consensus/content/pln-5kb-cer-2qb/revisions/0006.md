# UI Components

Define and componentize the primary UI components.

1. Application Chrome: Application Window, Title Bar, Window Size/Close buttons.
    - Decided: the desktop window uses Electron's hidden title bar with the native overlay buttons (minimize, maximize and close, drawn by Electron in the palette's colours and following the theme); the rest of the bar is a drag region filled by the Title Bar component. A browser shows the same bar as an ordinary top bar, without the window buttons and the drag region. No custom window buttons over IPC.
2. Application Title: The application title (e.g. Consensus), global application menu (including Help), and application status (like # of threads waiting on me).
    - Decided: one application menu in both hosts. The desktop's native menu bar goes; its items (Servers…, Reload, New window, Open folder in new window, Quit) appear in the application menu only when the desktop is the host. The server rows' menus (New Project, Import, Settings) stay in the tree. The status shows the count of threads waiting on me and the count of LLM runs in progress, each a link to its view.
3. Project Tree: The tree of server/project/item nodes, sorting and display options, and popup menus, etc.
    - Decided: the components are project-tree (the sort and the drop logic), tree-node (recursive, with a Depth binding, replacing the two ng-include templates), server-row (the row, its menu, its create form) and llm-fold. The popup menu stays the Menus service and its one popup element; Settings, Project settings and LLM Instructions stay the panels they are, opened by events.
4. Documents Pane: The pane which displays the detail of the currently selected item in the Project Tree. This includes a Tab Bar showing tabs for each open item. Selecting a Tab will show the Document Editor for that item type.
    - Decided: the pane picks the component by the tab's kind: document-editor for a plan or a document, llm-session for an LLM session, waiting-list for Waiting on you, and the start page with no tab open. The LLM session and Waiting views are componentized here as tab contents, unchanged inside.
5. Document Editor for a Plan:
    1. Editor Header: Item name, location, state, etc. Plus Editor Buttons.
    2. Edit view using Monaco.
    3. Formatted view in Html.
        - Display colorized text anchors.
        - Can click to focus thread.
        - Can be toggled show/hide.
    4. Edit view using CodeMirror 6.
        - Display colorized text anchors.
        - Can click to focus thread.
        - Can be toggled to replace the Monaco editor.
        - Default hides the Html view.
6. Item Thread Filters: Currently above thread list. These are the "Waiting on ..." and "Highlight ..." dropdowns. Changes to these dropdowns should be broadcast to other components. Specifically the Html and CodeMirror views, so they can update their thread displays. Filters are global and apply to all items, not just the selected one.
7. Item Threads: The list of thread cards according to the Thread Filters. Each card has components within it:
    1. Thread Header: Thread name, state, waiting on, anchor text, and delete.
    2. Thread Transcript: The transcript of thread messages with owners and timestamps, etc. Rendered markdown as an Html view.
    3. Thread Actions: A text input box and buttons for Replying, Resolving, etc.
