# Step 5: The editions cut

The four editions as the owner cut them on 2026-10-29: Sidecar opens a local folder; Client opens one remote project on one Server; Desktop opens several remote projects at a time from one or more Servers, never a local folder, at Personal; Server opens local folders and serves them to the others. Every edition serves the API, MCP and the instructions on its localhost address.

## The swap

The code has the Client and the Desktop the other way round, so the code bases swap rather than being rewritten:

- **desktop/** takes today's client code (main.js, Settings.js, preload.js): the Servers list, one sign-in through our Clerk instance, every added Server a root with its whole tree, New window on the same list. Titles, settings file (desktop.json: Servers, Theme, Scale, Remembered) and build/desktop.json follow. It sheds nothing of the client code; it gains the Personal check below.
- **client/** takes today's desktop code and is narrowed: one Server and one project per window, picked in the chooser (the Servers section of desktop/page/connect.html, over electron/Servers.js and src/Probe.js) or named on the command line: consensus-client [--connect <server> [<project>]] [--config <folder>], through App.Arguments with Rest false, --connect taking the saved Server's Name (the address is in client.json) and an optional second word, the project's id or name on it, else the Server's last project for that entry, else the chooser's project list; with no --connect the chooser; --port goes (the Client has no server of its own, its page server picks a free port, remembered) and a bare folder is refused as "not an argument the Client knows" (decided 2026-10-29); no local folders (open_folder_here, New project, the recent folders, desktop/Host.js and its routing, START.Run and the sidecar start leave), no Hosts file of its own (client.json: Servers with their last project, Theme, Scale, Remembered). Registered is the minimum, checked as today on the sign-in.
- **sidecar/** and **server/** are unchanged by the swap.
- Nothing shipped carries the old files, so there is no migration: each app reads its own file by its own name, and an older desktop.json with Recent and Hosts is read for Theme, Scale and Remembered alone.

## The Personal check

The Desktop signs in through Clerk in the page, as the Client does today, and the session's plan is the tier (Session.Plan). Below Personal the page shows the sign-in box with the license message (the Refusal shape session.js already has, Error license, Plan personal) in place of the Servers; the Servers popup and the roots are not loaded. The Desktop also hands the session token to the app (SetLicense), which writes the machine's current user (electron/CurrentUser.js), so the Server application on the same machine sees the sign-in; nothing in the Desktop reads that file for its own gate.

## The local API, MCP and instructions (electron/Proxy.js)

On the page server of the Client and the Desktop, beside /servers/<key>/api:

- **/api/*** forwards to the window's upstream: the Client's one Server; in the Desktop the current root, the one whose project is open (remembered as a page key, the first Server until one opens; decided 2026-10-29). The upstream changes as the person opens a project elsewhere, so an agent mid-task reads the instructions again when a call answers an unknown project; the instructions say so. A request with no Authorization gets the person's session token, which the page hands the app at load and at every refresh (Clerk refreshes it about once a minute; the bridge gains SetToken); a request carrying its own token is passed as it is. The header X-Consensus-Service is passed through, so an agent beside the window posts as "<service> by <person>".
- **/instructions** is composed locally with Instructions.Make: This server names the local address, the window's project (the Client's one; the Desktop's current one, with the note that the others are reached under /servers/<key>), and says a request with no token acts for the signed-in person; the guide is the common one.
- **/api/mcp** is Mcp.js over a remote operations adapter: the definitions from Operations.Definition, Perform( name, participant, args ) turning the call into the upstream REST request through Operations.Route with the token; initialize, ping, tools/list and tools/call as on a server. The stdio shim reaches it as it reaches any server, with --server http://127.0.0.1:<page port>.
- The upstream does the authorizing; the proxy refuses nothing of its own.
