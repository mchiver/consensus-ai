# The Server

Two applications, drawn from the owner's direction of 2026-10-26 after plan Rearchitecturation (pln-gkn-zlj-42q) was built: the **Desktop**, which shows one project at a time and exposes it to connections on localhost, and the **Server**, a second Electron application that holds the machine-wide configuration and exposes projects to public connections. Each can be reached from a browser window as well. The Server is a server manager: its window is the extended project tree and the resources around it, and it does no content work in the projects.

## What the Desktop is

A window holds one project, opened from a folder, and the server inside it, the sidecar, serves that project on localhost: to the agent beside the window, and to a browser on this machine that opens the sidecar's address and gets the same page. The Desktop needs no sign-in on its own; it signs in when it wants a Server's resources, a project the Server serves or the Server's LLM connections, and that sign-in is what the Server asks of every client. This is what Rearchitecturation built, with what it put on the Desktop for the Host taken off again (below).

## What the Server is

A second Electron application, with its own entry point and its own installer, run on the machine that serves a team. It holds the machine-wide configuration: the settings (Name, Scope, Port, States), the registry of projects with their Mounted switches, the users and their roles in each project, the LLM connections and the tasks, the Clerk section, and the Server's own log. Its process runs the server that exposes the mounted projects to public connections: the API for Desktop thin clients and agents, and the content page to any signed-in client, since the Server cannot tell, and need not, whether a request is a browser or a Desktop. Its window is the **manager**: the extended project tree, each registered project a row with its Mounted switch, its Users folder and its roles, and beneath them the LLM connections, the tasks, the accounts and the settings; a project row opens nothing, there is no editor and no threads pane, and no content is read or written there. The same manager page is served at an address of its own, so a browser window on the machine, or an Administrator elsewhere, can open it; it is the Administrator's page, and on a Local Server the owner's.

## The command line

- `consensus-desktop [<folder> | --connect <name>]` is the Desktop, as it is.
- `consensus-server [--config <folder>] [--port] [--scope]` is the Server, its window the manager; `--headless` runs it with no window, which is what the Docker image and `npm start` run. The word `serve` of the headless program is this form; `consensus serve` stays as its alias for a plain node install.
- The manager's address is the Server's with a path of its own (`/manage`), served to the Administrator alone.

## What leaves the Desktop

Start the Server Host, Open the Server Host and Stop the Server Host leave the Desktop's menus; the routing of a mounted folder to the Host's project stays (a folder the Server serves opens as that project when the Server runs); Connect to Host stays, renamed Connect to Server; the Desktop's reading of the Server's consensus.json for the connections and tasks stays for a machine that runs both, and a Desktop on another machine takes them from the Server it is connected to. The tiers stay as Step 6 built them: Free is the Desktop and the sidecar, Personal the LLM tasks and the thin client, Professional runs the Server bound to the network and is its Administrator; a Personal license runs the Server on localhost.

## The code

One repository, two Electron entry points: `desktop/` as it is, and `server/` for the Server (its main process, its window, its page), both over `src/` and the page's components in `public/components/`; the manager page is built from the components the tree already has (project rows with the mount switch, the roles folder, the LLM fold, the Users fold, the settings popup) with no editor, no threads pane and no tabs. The Server's window closing does not stop the server: the Server keeps running from the tray until Quit, so a team's connections outlive the window. `package.json` gains the second executable and `npm run dist` builds both installers.

## Steps

1. **The manager page.** The page at `/manage`, the Administrator's: the extended tree with the mount switches, the roles, the accounts, the connections, the tasks and the settings, nothing of content; served by the Server; a browser test.
2. **The Server application.** `server/`: the Electron main process running the server in-process, the window on the manager page, the tray with Open, Quit and the address, the log; `consensus-server` on the command line with `--headless`; the installer.
3. **The Desktop's split.** The Host items off the Desktop's menus, Connect to Server, the sign-in only when Server resources are wanted; the Desktop test and the smoke follow.
4. **The guide.** The Server page of the guide rewritten for the application, Getting started's Server section, the readme, the pictures.
