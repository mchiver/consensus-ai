# Worker Electron App

Create an Electron app for the worker server: one desktop window that configures the LLMs, spawns worker servers, one per local path, and shows each worker in a tab of its own, with Start, Pause, Resume and Stop.

## Why

- A worker is started from a shell today, one `node bin/worker.js --settings <file>` per worker, each with a hand-written worker.json and its page in a browser tab; every worker started from one checkout shares `~worker/jobs.json`.
- The dev machine holds several repos, and each wants a worker of its own with the same LLMs. The app keeps the LLMs in one place and gives each repo a worker in a few clicks.

## The app

- Electron, in this repo, under app/: `app/main.js` (the main process), `app/preload.js` (the bridge) and the window's page in `app/page/` (AngularJS and Bootstrap, as the worker's page, with light/dark and small/normal/large through the same `theme.js`). `electron` is a devDependency of the root package, and `npm run app` starts it. No installer or packaging in this plan; the app runs from the checkout.
- The main process runs the workers in-process, through `Start` from `src/Worker.js`, one call per worker, with the same `Vendor` the command line passes; no child processes. Each worker keeps its own Express page on its own port, as today, so it can still be opened in a browser.
- The window is a tab strip. The first tab, **App**, holds the settings: the Consensus server, the LLMs and the list of workers. After it, one tab per worker.
- The page talks to the main process over the preload's bridge (IPC): the app's settings, the workers with their status, and the actions on them. The app's own page loads from a file; nothing new is served over HTTP.
- Electron's Node must be 22 or newer, as `engines` in package.json says, since the worker uses fetch and AbortSignal.any.

## Settings

The app keeps app.json in Electron's user-data folder (`%APPDATA%/consensus-worker/app.json` on Windows):

```
{
  "Consensus": { "Url": "http://cube4:3500" },
  "Inference": [
    { "Name": "Claude CLI", "Type": "claude-cli", "Command": "claude", "Model": "sonnet" },
    { "Name": "Ollama", "Type": "ollama", "Url": "http://127.0.0.1:11434", "Model": "glm-5.3:cloud" }
  ],
  "Workers": [
    {
      "Name": "Consensus",
      "Token": "…",
      "Root": "W:/code-projects/orgs/mchiver/consensus.git",
      "Include": [],
      "Exclude": [ "~data/**", "node_modules/**" ],
      "Build": { "Remote": "origin", "Commands": [ "npm test" ] },
      "AutoStart": true
    }
  ],
  "MaxRounds": 30,
  "TimeoutSeconds": 900
}
```

- **Consensus** is the one server every worker connects to.
- Each worker has its own **Token**, generated by the app when the worker is added and shown with a Copy button. The owner adds it to the server's consensus.json under Workers with the worker's Name, as for any worker today; Consensus tells workers apart by their tokens, so two workers cannot share one.
- **Inference** is the app's list of LLMs, the same items as worker.json's Inference items. Every worker carries all of them.
- Each **Worker** is one workspace: Root, Include, Exclude and Build, as worker.json's Workspace item. The workspace it offers to Consensus is named after the worker.
- **MaxRounds** and **TimeoutSeconds** are the app's, for every worker.
- When a worker starts, the app writes its settings in today's format to `<user data>/workers/<Name>/worker.json`: Name, Consensus (the app's Url, the worker's Token), Web (127.0.0.1 and a free port the app picks), Items (the app's Inference items and the worker's one Workspace), MaxRounds and TimeoutSeconds. Its jobs go in `<user data>/workers/<Name>/jobs.json`. That file is what `bin/worker.js --settings` reads, so a worker the app configured can also run from a shell. Saving a change to a running worker, or to the LLMs, rewrites the files of the running workers and reloads them, as Reload does today.

## The App tab

- **Consensus**: the Url.
- **LLMs**: the list, each with Name, Type (claude-cli or ollama) and the type's fields: Command and Model for claude-cli; Url and Model for ollama, the Model picked from the ones the Ollama server lists, with Refresh. Add, edit and remove; **Check** runs the CLI with `--version` or asks Ollama for its models, and shows what came back.
- **Workers**: the list, each with its status (stopped, starting, connected, offline, paused, working), its page's address and Start or Stop; Add, Edit and Remove. The form has Name, Root (with a folder picker), Include and Exclude (one pattern per line), Build's Remote and Commands (one per line, or none for a worker that does not build), AutoStart, and the Token with Copy.
- The app validates through the worker's own `Validate`: it builds the worker's settings as they would be written and shows the problems on the form. Nothing is saved while there are problems. Removing a running worker stops it first, and asks.

## A worker's tab

- One tab per worker, named after it, with a dot for its status. A running worker's tab shows the worker's own page (`public/worker/`), loaded from the worker's port in an embedded web contents view (Electron's WebContentsView), so what it shows and does (the connection, the job and its tool calls, the jobs, Pause, Resume, Cancel, Reload, Commit and Push) is what it is in a browser, unchanged.
- Above the page, the app's bar for the worker: **Stop** and **Open in browser**. Pause and Resume stay the worker's own buttons, on its page. Stop cancels a running job, as Close does today (Consensus is told the job was cancelled), and closes the worker; Consensus sees it go offline.
- A stopped worker's tab shows a card in place of the page: when it stopped and why (stopped by you, or its error), and **Start**.

## Starting and stopping

- On open, the app starts every worker marked AutoStart; the others wait for Start.
- Closing the window stops every worker (a running job is cancelled, and Consensus told) and quits the app. No tray icon.
- A worker that cannot start (settings with problems, a Root that is gone, a port that cannot be opened) shows the reason on its tab and stays stopped; the others start.
- The app assigns each worker's port when it starts (a free one); the address is shown on the App tab and the worker's tab, and copied with a click.

## What stays the same

- `src/Worker.js`, `bin/worker.js`, the worker's page and its tests are not changed: the app is a second way to start what exists.
- Consensus's side (`src/Workers.js`, consensus.json's Workers) is unchanged; a worker the app runs is a worker like any other.

## Tests

`node --test`: the app's settings module (reading and writing app.json, building a worker's worker.json from it, the problems it reports) and the worker manager with a fake Start (start, stop, autostart, reload on a saved change, a worker that fails to start while the others run). The Electron window itself is checked by hand; no Electron test harness in this plan.
