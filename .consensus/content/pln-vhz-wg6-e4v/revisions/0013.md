# Usage Scenarios

Three LLM tasks a person starts with a button, and the guide page that explains the ways of working. Identity is User Management's: a run is the person who pressed the button, allowed what their role allows. Enhance and Run write; Explain (added 2026-10-18; its four decisions taken the same day, the thread resolved with no reply: the person and the Owners see a conversation, the files are in the package, it is kept in the project, it is Step 3) reads only, and is the one task a Watcher has.


## Enhance

- A button on a Draft, beside Run, for Owners and Members: **Enhance**, with a text box for custom instructions ("replace this with a detailed plan; open threads for anything unclear" is the default). It runs the project's chosen LLM connection once with the plan, the Readme and the instructions, as a run of the presser.
- What the run posts is what any turn posts: the new text as a revision, and a contested thread for each question. The owner answers the threads and presses Enhance again, or Run, until the threads are resolved.
- Enhance is Run with a different package: the one-shot gets the plan and the instructions, not the waiting threads.


## Build options

- The Run button on a Plan state gets two checkboxes, remembered per project: **Git sync** (pull before the run, push after a commit) and **Auto-commit** (commit the working tree when the build log is accepted, titled after the plan, the build log as the message). Both off by default; both need the project folder to be a git checkout, which the run reports when it is not.
- The build log thread is the commit message's source, as the build loop already says.


## Explain

- A third button beside Run and Enhance, on a project, for every role: **Explain**, the one a Watcher has. It opens a **conversation tab** for that person and that project: a question at the bottom, the exchange above, newest last. The feature is a conversation with the project, for a supervisor as much as for a member: what the project is, who did what and when, what is planned, why a thread was resolved the way it was.
- A question runs the project's LLM connection once, as a run of the presser, with the project packaged read-only: the Readme and the Context folder, the plans with their states, the threads with who said what and when, the revisions with who applied them, the run records, and the project folder's files as the connection's packaging lists them. The answer goes into the tab and nowhere else: the run posts nothing to any plan.
- It is read-only by construction. The run holds a run-scoped token carrying the presser's role, so a Watcher's Explain cannot post, edit or apply whatever the model tries; a local model through Ollama gets the read tools only (no write, no shell).
- The conversation is kept with the project, per person, in the project's `.consensus`, and shown to that person and to the project's Owners; the person clears it. A run counts like any run in the quota.
- Explain is the LLM Session pane with the project as its subject and no write; the pane's conversation shape is reused.


## The guide page

- `docs/guide/ways-of-working.md`: the three ways in prose, each a few paragraphs and one picture: the **agent session** on the same machine (it reads /instructions, understands "check consensus", "your turn", and keeps the project's files; changes appear in Consensus at once; nothing it does not say "your turn" to is read); the **server's LLM connections** (a person presses Run, Enhance or Explain; Claude Code as a one-shot or a local model through Ollama; the run is theirs); and **plan building** (a rough sketch, Enhance, answer the threads, repeat until the plan stands; then Run to build); and a paragraph on **Explain**, the conversation with the project that every role has.
- Linked from Getting started and the Features page.


## Steps

1. Enhance, with its package and its smoke check.
2. The Build options.
3. Explain: the conversation tab, the read-only package, the run-scoped role, the read tools for local models, the smoke check as a Watcher.
4. The guide page and the pictures.
