# Consensus Project Features

Using Consensus with a brownfield plan suffers from a lack of context when attempting to build on top of an existing corpus without further context.

We need to define a Project mechanism that collects proposals, plans, and context for a single project.

- The sidebar should now display a Project tree that lists projects and all of the items in a project.
- Project items are:
    - Plans, what we edit in Consensus. Plans can be one of the following states:
        - Proposal: Open for discussion. The owner promotes it to a Plan, and only when all of its threads are resolved.
        - Plan: All threads are locked and can be manually demoted to a Proposal or manually promoted to Completed.
        - Completed: The final and read-only stage of a Plan.
    - Plain markdown files, no comments or stages.
    - Filespecs into the corpus.
    - Folders to organize any combination of other items. Copy-Paste and Drag-Drop should be supported.
- All Project items are available to the LLM through direct query and vector search in order to build context.
- Only a single Project should be open/expanded at a time. When tree root is expanded, then the other collapse.
- The sidebar can still have a shortlist of:
    - Open (unapproved) Proposals
    - Open (uncompleted) Plans
    - Trash
