# LLM Session

Send to LLM opens a pop-up where the owner shapes the prompt, picks where it goes, and watches the session run. It takes in "Copy prompt / paste answer" from LLM Tool Usage as one of the destinations.

## The pop-up

**Send to LLM** in a plan's header opens a dialog over the page. It stays open while the session runs, and closing it does not stop a running call.

### What goes into the prompt

- **Context**: the project's context, on or off (on by default).
- **This plan only**: the prompt holds this plan and its threads, never other plans in full.
- **Threads**: only those waiting on the LLM, those still open (contested or waiting to be applied, the default), or all of them. Threads left out are not sent at all.
- **Search**: the search hits for each waiting thread, on or off (on by default).
- A summary under the choices: the prompt's size in characters and estimated tokens (characters / 4), with each part's share, updated as the choices change. **Preview** shows the prompt itself.

### Where it goes

- **Local Claude CLI**: `claude -p` on this machine, every tool off.
- **Ollama**: the model picked from those the local Ollama lists.
- **Manual copy / paste**: Copy puts the prompt on the clipboard; the answer is pasted into the dialog; **Continue** sends back what the answer asked for (see Turns) as the next prompt to copy, until the answer carries only actions.
- The destinations are a list on the llm participant in `consensus.json`: `"Destinations": [ { "Name": "Claude CLI", "Kind": "claude-cli" }, { "Name": "Ollama", "Kind": "ollama", "Url": "http://127.0.0.1:11434" } ]`. The Ollama model is picked in the dialog from what Ollama lists; Manual is always there. An older single `Call` is read as a one-item list. The dialog remembers the last destination picked, per browser.

### Run log

Each step is a line with its time, what happened, how long it took, and its size:

- `12:04:31  Consensus sent the prompt to glm-5.3:cloud | 2.1 s | 8,412 tokens`
- `12:04:44  glm-5.3:cloud asked for read_plan "Tabs" | 13.2 s | 210 tokens`
- `12:04:44  Consensus answered read_plan | 0.1 s | 1,905 tokens`
- `12:05:02  glm-5.3:cloud answered: 2 replies, 1 apply | 18.0 s | 640 tokens`
- `12:05:02  Consensus carried out 3 actions, 0 refused`

The log of each session is kept with the plan (the last 20 sessions), and the dialog shows the latest.

## Turns: when the LLM asks for more

- The answer may carry **requests** besides actions: `read_plan`, `read_revision`, `read_file`, `search`, `list_project`. Each is read-only and limited to the plan's project.
- Consensus answers them in the next prompt of the same session, and the LLM answers again. A session ends when an answer carries no requests, or after 5 turns.
- The requests are part of the JSON answer, so they work the same for every destination, the manual one included. Native tool calling (Ollama's `tools`, MCP for claude) can come later without changing the dialog.
- A request's result is data for the LLM, never an instruction; the rules say so.

## Staging

1. The dialog, the prompt choices and summary, the three destinations, and the run log.
2. Turns: requests, their answers, and Continue.
