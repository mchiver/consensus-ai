# Project Context Server

Consensus works best when used in conjunction with a local agent running in a harness like Claude Code. A local agent provides an interactive way to build a context and prompt an inference engine.

Without a local agent, we need a context server that can connect to a file system (corpus) and manage LLM connections (inference).

The context server receives connections from a Consensus server and provides context regarding the corpus. This will be read-only access for now. A proxy can also manage connections to local inference resources (e.g. Ollama, Claude CLI).

A proxy is configured using an array of json structure containing named filepaths/filespecs that constitute the corpus and named connections that route LLM connections.

Consensus registers running proxy servers by connecting to them and querying for their Corpus and Inference items. Consensus will offer these items when selecting for "Send LLM" targets and context lookups to satisfy LLM exploratory requests.

```js
// Corpus
{
    Kind: "Corpus",
    Name: "", // Unique name on this server
    Filespec: "", // Path to the root of the corpus (e.g. C:\project)
    Disallowed: [], // Array of filespecs that are excluded from the corpus.
    Allowed: [], // Array of filespecs that are included in the corpus. If empty, then all files are included.
}
// Inference
{
    Kind: "Inference",
    Name: "", // Unique name on this server
    Type: "", // Either CLI or Ollama
    Connection: {}, // Type based structure
}
```
