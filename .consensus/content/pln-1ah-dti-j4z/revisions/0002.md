# Proxies

Consensus works best when used in conjunction with a local agent running in a harness like Claude Code. A local agent provides an interactive way to build a context and prompt an inference engine.

Without a local agent, we need a proxy that can connect to a file system context (corpus) and manage LLM connections (inference).

The proxy runs as a server that receives connections from a Consensus server and provides readonly context regarding the corpus. This will be read-only access for now. A proxy can also manage connections to local inference resources (e.g. Ollama).

A proxy is configured with a json structure containing named filepaths/filespecs that constitute the corpus and named connections that route LLM connections.

Consensus registers running proxy servers through configuration. Each configuration entry has a kind: either a Corpus or an Inference.
