# Rearchitecturation

- Split the current application into two parts:
  - Desktop: the application that works with a singe Project (folder) at a time
  - Server Host: the application which exposes Projects to a network. The Server Host also own all users and llms.

## Desktop

Each instance opens a single project at a time.
Can create a consensus project in a new folder, connect to an existing local folder, or connect to a project mounted on a Server Host.

### Sidecar Usage
Exposes the project via API and MCP on localhost for sidecar usage. Use a range of ports so that concurrent instances will work.
A sidecar session initiaizes when the LLM Instructions are copied into the LLM's session.

## Server Host

A separate application or mode of the Desktop application.
Uses the system's user folder (`~`) to store settings global to the system.
Manages the project registry for this machine. Projects can be mounted and unmounted for remote access.
Manages Users and permissions for mounted projects.
Manage LLM connections and tasks for mounted projects.

## Licensing

Licensing ranges from None to Host with each level granting additional privleges.

### None
- The freely available feature set.
- Can run Desktop to work with projects in local folders.
- Can use Desktop to start a local server to expose a project on an unused port.
- Can copy Sidecar instructions for project in Desktop.

### Member
- Can use all LLM Tasks in Desktop.
- Can connect Desktop to a Server Hosted project.
- Can expose the Server Host to local connections.
- Can use Server Host to manage mounted projects.
- Can use Server Host to manage LLM connections.
- Can use Server Host to manage Users.

### Host
- Can expose the Server Host to remote connections.
