# Workers

The LLM takes its turn where the code is, with tools the way Claude Code works, instead of Consensus shipping files to it. A worker beside the code runs two kinds of job, each a Subplan: **Review** (read-only turns on a plan's threads) and **Build** (implementing a plan). This plan is what both share: the worker, Consensus's side, the job routes and the worker's page.

## Why

- Consensus runs on cube4; the code and the LLMs that can read it (claude, Ollama) run on the dev machine.
- Attached zips are stale copies. Linked corpora are live, but through the context server's own file and search routes, a second index, and Consensus calling into the dev machine (cube4 lists no context servers today).
- Requests (plan LLM Tool Usage, option 2) give the model a few rounds of asking, each a whole new prompt. Claude Code does better with a real tool loop: glob, grep and read, as many times as it needs, in the repo itself.

This plan is option 4 of LLM Tool Usage (a tool loop), run on the worker instead of in the server, and a Subplan of it.

## The worker

The context server becomes the worker: `src/Worker.js`, `bin/worker.js`, settings in `worker.json`. The name "context server" is retired everywhere: code, settings (`Workers` in `consensus.json` replaces `ContextServers`), the page and the guide. It runs on the machine that holds the code, and connects out to Consensus; Consensus never connects to it.

```
{
  "Name": "Workstation",
  "Consensus": { "Url": "http://cube4:3500", "Token": "<this worker's token>" },
  "Web": { "Host": "127.0.0.1", "Port": 3700 },
  "Items": [
    { "Kind": "Workspace", "Name": "Consensus", "Root": "W:/code-projects/orgs/mchiver/consensus.git", "Include": [], "Exclude": [ ".git/**", "~data/**" ] },
    { "Kind": "Inference", "Name": "Claude CLI", "Type": "claude-cli", "Command": "claude" },
    { "Kind": "Inference", "Name": "Ollama", "Type": "ollama", "Url": "http://127.0.0.1:11434", "Model": "glm-5.3:cloud" }
  ],
  "MaxRounds": 20,
  "TimeoutSeconds": 600
}
```

- A **workspace** is a folder read as it is now. Include, Exclude and every .gitignore under Root choose the files, as corpora do today. Nothing is indexed. Build adds its own settings to a workspace (plan Build).
- **Inference** items are the models the worker can run, as today.
- The worker runs one job at a time, in the order Consensus gives them.

## Consensus's side

- `consensus.json` lists the workers it accepts: `"Workers": [ { "Name": "Workstation", "Token": "…" } ]`. A worker's token is used only on the worker routes; what a worker returns is carried out as the `llm` participant.
- `src/Workers.js` replaces `src/ContextServers.js`: the workers last heard, their workspaces and inference items, and a queue of jobs.
- A project names one workspace (`Workspace: { Worker, Name }`), chosen on the project's page from the workers' workspaces.
- A worker's inference items are destinations, "Workstation / Claude CLI". A worker not heard from in 60 seconds shows as offline, and its destinations cannot be chosen.
- The plan page has two buttons, **Review** (it replaces Send to LLM) and **Build**. Each queues a job of its kind (plans Review and Build).

Routes, each with the worker's token:

- `POST /api/workers/hello` `{ Workspaces, Inference }`: what the worker offers, at start and when its settings change.
- `GET /api/workers/jobs`: held open up to 30 seconds; answers the next job for this worker (`Kind`: Review or Build), a change to one of its jobs (a build accepted or sent back), or nothing. The worker asks again at once.
- `POST /api/workers/jobs/<id>/tool` `{ Tool, ... }`: a plan tool (list_project, read_plan, read_revision, search), answered by the same code as Requests today, within the job's project.
- `POST /api/workers/jobs/<id>/step` `{ Text }`: a line for the run log ("Read src/Api.js", "Grep 'caller_for'", "Committed 3e36ad6").
- `POST /api/workers/jobs/<id>/answer` `{ Answer, Usage }` or `{ Error }`: the job's answer, carried out as its kind says.

## The worker's page

The worker serves its own page at `Web.Host:Port` (127.0.0.1:3700 by default; the owner only, no token, as Consensus on a private network). Express, AngularJS and Bootstrap, light/dark and small/normal/large, like Consensus's page, in `public/worker/`. Updates arrive live (server-sent events).

It shows:

- **The worker:** its connection to Consensus (online, last heard), its workspaces and inference items.
- **The current job:** its kind, project, plan, workspace, model, and how long it has run.
- **Tool calls:** each call as it happens, with its input and a short piece of its result (Read src/Api.js lines 1 to 200; Grep "caller_for", 4 matches; a plan tool and what it named).
- **The answer:** the LLM's final response in full: a review's JSON, or a build's log.
- **Jobs:** the queue and the last 50 jobs (kept in `~worker/jobs.json`), each opening to its tool calls and answer.

And administers it:

- **Pause** and **Resume** taking jobs; **Cancel** the running job (its answer is reported as an error).
- **Reload** the settings.
- **Commit**, **Push** and **Remove worktree** on a build (plan Build). Each queues the step; the worker runs its queue in order and shows each step's result.

## What goes away

- Linked corpora, the context server's corpus routes (files, file, search) and their indexing.
- Remote destinations (Consensus calling a context server's inference route): workers take their place.
- Requests stay for destinations Consensus calls itself and for Manual (copy and paste).

Attached zips stay as they are, with their search and Requests, for a project with no worker and for files that are not a codebase.

## Tests

`node --test`: the job routes (hello, long poll, tool, step, answer, a stale worker going offline); the worker with fake callers; the worker's page and its events (`test/Ui.test.js`, headless). Each Subplan tests its own job.
