# Workers

The one-shot LLM takes its turn where the code is, with read tools the way Claude Code works, instead of Consensus shipping files to it.

## Why

- Consensus runs on cube4; the code and the LLMs that can read it (claude, Ollama) run on the dev machine.
- Attached zips are stale copies. Linked corpora are live, but through the context server's own file and search routes, a second index, and Consensus calling into the dev machine (cube4 lists no context servers today).
- Requests (plan LLM Tool Usage, option 2) give the model a few rounds of asking, each a whole new prompt. Claude Code does better with a real tool loop: glob, grep and read, as many times as it needs, in the repo itself.

## The worker

The context server becomes the worker: `src/Worker.js`, `bin/worker.js`, settings in `worker.json`. The name "context server" is retired everywhere: code, settings (`Workers` in `consensus.json` replaces `ContextServers`), the page and the guide. It runs on the machine that holds the code, and connects out to Consensus; Consensus never connects to it.

```
{
  "Name": "Workstation",
  "Consensus": { "Url": "http://cube4:3500", "Token": "<this worker's token>" },
  "Items": [
    { "Kind": "Workspace", "Name": "Consensus", "Root": "W:\code-projects\orgs\mchiver\consensus.git", "Include": [], "Exclude": [ ".git/**", "~data/**" ] },
    { "Kind": "Inference", "Name": "Claude CLI", "Type": "claude-cli", "Command": "claude" },
    { "Kind": "Inference", "Name": "Ollama", "Type": "ollama", "Url": "http://127.0.0.1:11434", "Model": "glm-5.3:cloud" }
  ],
  "MaxRounds": 20,
  "TimeoutSeconds": 600
}
```

- A **workspace** is a folder read as it is now. Include, Exclude and every .gitignore under Root choose the files, as corpora do today. Nothing is indexed.
- **Inference** items are the models the worker can run, as today.

## Consensus's side

- `consensus.json` lists the workers it accepts: `"Workers": [ { "Name": "Workstation", "Token": "…" } ]`. A worker's token is used only on the worker routes; what a worker returns is carried out as the `llm` participant.
- `src/Workers.js` replaces `src/ContextServers.js`: the workers last heard, their workspaces and inference items, and a queue of jobs.
- A project names one workspace (`Workspace: { Worker, Name }`), chosen on the project's page from the workers' workspaces.
- A worker's inference items are destinations in the Send to LLM dialog, "Workstation / Claude CLI". A worker not heard from in 60 seconds shows as offline, and its destinations cannot be chosen.

Routes, each with the worker's token:

- `POST /api/workers/hello` `{ Workspaces, Inference }`: what the worker offers, at start and when its settings change.
- `GET /api/workers/jobs`: held open up to 30 seconds; answers the next job for this worker, or nothing. The worker asks again at once.
- `POST /api/workers/jobs/<id>/tool` `{ Tool, ... }`: a plan tool (list_project, read_plan, read_revision, search), answered by the same code as Requests today, within the job's project.
- `POST /api/workers/jobs/<id>/step` `{ Text }`: a line for the run log ("Read src/Api.js", "Grep 'caller_for'").
- `POST /api/workers/jobs/<id>/answer` `{ Answer, Usage }` or `{ Error }`: the answer, carried out as a session's answer is today.

## A turn

1. The owner sends to a worker destination. Consensus packs the prompt as today (rules, context, proposal, threads, plan search hits) and queues a job: the prompt, the answer's schema, the workspace, the inference item and model.
2. The worker takes the job and runs the model in the workspace, with the tools below, until it gives its answer or reaches MaxRounds or TimeoutSeconds.
3. The answer is the same JSON as today (reply, apply, context), and Consensus carries it out through the same rules. A worker turn has no Requests: the tools replace them.

## Tools

File tools, read-only, within the workspace's Root and its Include and Exclude:

- **glob** `{ Pattern }`: the paths that match.
- **grep** `{ Pattern, Glob?, IgnoreCase? }`: matching lines with their paths and line numbers.
- **read** `{ Path, Offset?, Limit? }`: a file's lines, numbered.

Plan tools, answered by Consensus: list_project, read_plan, read_revision, search.

- **claude-cli:** `claude -p` in the workspace's Root with `--tools "Read,Grep,Glob"`, `--output-format stream-json` (each tool call becomes a run step), `--json-schema` for the answer, `--max-turns` from MaxRounds, and `--strict-mcp-config --mcp-config` naming the plan tools' MCP server: `node bin/worker.js --mcp`, a small stdio JSON-RPC server (initialize, tools/list, tools/call) written without a dependency, which passes each call to the tool route.
- **ollama:** the worker runs the loop itself through `/api/chat` with `tools`: glob, grep, read and the plan tools. After MaxRounds, or when the model stops calling tools, it asks once more with `format` set to the answer's schema.
- No shell, no git, no writing, no web.

## What goes away

- Linked corpora, the context server's corpus routes (files, file, search) and their indexing.
- Remote destinations (Consensus calling a context server's inference route): workers take their place.
- Requests stay for destinations Consensus calls itself and for Manual (copy and paste).

## Tests

`node --test`: the job routes (hello, long poll, tool, step, answer, a stale worker going offline); the worker with fake callers; the Ollama loop against a fake Ollama; glob, grep and read refusing paths outside Root or left out by Exclude and .gitignore.
