# UI Tweaks II

Ten page changes: the project tree, the threads pane, the session panel and the buttons. Each choice made here is remembered per browser (localStorage), like the Threads and Preview toggles. Nothing changes in the data folder; the server changes are two small ones (Created in the tree, and Comment and resolve).

## Project tree

1. **Show / hide the tree.** A button at the left end of the tab bar (always visible, a sidebar icon) hides or shows the sidebar and its splitter. The document area takes the space.
2. **Updated stamps.** A **Show updated** toggle in the sidebar top shows each item's last update, muted and right-aligned on its row, in the same short form as reply stamps (full time on hover). It applies to plans, Subplans, documents, corpora and project headings; folders have no stamp.
3. **Sorting.** A **Sort** picker in the sidebar top:
   - **None:** the name, in the manual order (today's tree).
   - **Name:** the name, alphabetical (case-insensitive).
   - **Created:** the item's created date (yyyy-mm-dd, local time), then its name; oldest first.
   - **Updated:** the item's updated date (yyyy-mm-dd, local time), then its name; oldest first.

   Sorting applies at every level: inside each folder, and to each plan's Subplans. Documents and corpora sort with plans. Folders stay above the other items, sorted by name. The projects keep their manual order. While a sort other than None is on, dropping on a row's top or bottom edge (reordering) is turned off; moving into a folder, onto a plan or onto a project heading still works. The tree's items gain `Created` beside `Updated` (`src/Api.js`, the tree views) for this.

## Threads pane

4. **Comment and resolve.** The compose card gets a **Comment and resolve** button (owner only) beside Comment: it posts the thread already resolved, so the comment is the outcome the LLM applies, as with Reply and resolve. One call: `POST /api/proposals/<id>/threads` takes `Resolve: true`, refused for anyone but the owner.
5. **New Comment.** "Comment on the whole document" becomes **New Comment**. It still starts a whole-document thread; **Re-anchor** is now offered on whole-document threads too, to anchor it to a passage afterwards.
6. **Filter defaults to Waiting on me.** Each tab keeps its own filter, and a newly opened tab starts at **Waiting on me**.
7. **Highlight all or open.** A **Highlight** picker at the top of the threads pane: **All threads** (today's behavior) or **Open threads**, which highlights only contested threads in the read view; resolved and applied threads are not highlighted.

## Session panel

8. **Centered, movable, sizable.** The session panel opens centered in the plan's content area. Dragging its heading moves it and its corner resizes it, kept within the content area and no smaller than a usable minimum. Its last position and size are remembered (one for all panels); a **Reset** on the heading puts it back in the center.

## Buttons

9. **Color and icons.** Buttons get color by purpose: primary actions blue, resolve and accept green, delete red, everything else a tinted neutral, in both themes. Each gets an SVG icon before its label, and the icon-only row buttons (×, ✎, ⧉, +, ↗) become SVG icons with titles. The icons are inline SVG, one symbol set in `public/index.html`; no new dependency.
10. **Pop on hover.** On hover every button lifts slightly, deepens its color and gains a soft shadow; pressed, it settles back. Kept quick (about 120 ms) and turned off under `prefers-reduced-motion`.

## Checks

The UI test (`test/Ui.test.js`) covers: tree hide/show, each sort order and the stamps, Comment and resolve (the API test covers `Resolve: true` and its refusal for a non-owner), the New Comment label and re-anchoring a whole-document thread, the default filter, the Highlight picker, and the session panel's move, resize and reset.
