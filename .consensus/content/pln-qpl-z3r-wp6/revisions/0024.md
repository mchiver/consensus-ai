# UI Tweaks VI

- On a resolved thread, the "Reply" button reads "Reply and Contest" and takes the color of the Contested thread state: the reply reopens the thread, which stays open and contested. On a contested thread the button stays "Reply". "Reply and resolve" and "Comment and resolve" are unchanged.

- Saving an edited document (the Save button or `Ctrl+S`) stays in Edit. After the save the editor's base revision is the new one, so a further edit saves cleanly; the toast (below) is the sign that it happened. A save refused because the proposal moved on stays in Edit with the error, as now. The Read button and `Ctrl+E` are how one leaves Edit.

- A menu bar above the project tree, in place of the Project and Import buttons, with the menu "Help":
    - About:
        - Consensus version and the server's name, from GET /api/me (already loaded)
        - link to source: https://github.com/mchiver/consensus-ai
        - link to online guide: http://consensus-ai.liquicode.com (in the desktop, links open in the system browser)
        - summary of each project showing total number of threads, number contested, number waiting on me, and number waiting on LLMs. The counts are sums of the Tally the tree already loads for each plan (archived plans left out), no new route; "waiting on LLMs" sums WaitingOn over every participant whose Role is llm. In the desktop, one block per server headed by its name, "waiting on me" counting that server's own Me.
    - New Project, Import Project and Settings are not in the menu bar: they are the server row's menu (which has them already), so each is specific to its server. The server row's Settings button stays.
    - Hotkeys: The list of available hotkeys

- Hotkeys. One table in a new `public/js/hotkeys.js` factory ({ Keys, Label, When, Act } per row) drives both the Help > Hotkeys page and one window keydown listener; Ctrl+E (header.js) and Ctrl+C/V (sidebar.js) move into it, Ctrl+S stays Monaco's binding but is listed, Escape stays with the menu and popups (each closes itself) and is listed. Ctrl+S and Ctrl+E work wherever the page has focus, the editor included; Ctrl+C and Ctrl+V are the browser's own while typing or with text selected; the Ctrl+Shift and tab keys work everywhere; no hotkey but Escape fires while a popup is open. The Hotkeys page shows Cmd for Ctrl on a Mac.
    - Ctrl+E: switches between Read and Edit. From Edit with a dirty, unrefused edit it saves and then goes to Read (Ctrl+S saves and stays); a refused save stays in Edit with the error; with nothing to save it just goes to Read. The Read button keeps today's behaviour, keeping the draft.
    - Ctrl+S: saves in the editor and shows a toast on success. The toast is new: a small Toast factory (`public/js/toast.js`) with one element at the bottom of the main area; Show( Text ) fades it in and out over about two seconds, a later message replaces the earlier. Used here for "Saved, revision N", and by Copy and Paste, which confirm nothing today.
    - Ctrl+C and Ctrl+V: copy and paste an item's export on the open item.
    - Escape: closes menus and popups.
    - Ctrl+Shift+E: show/hide the project tree explorer
    - Ctrl+Shift+T: show/hide the threads
    - Ctrl+Shift+C: add a document level comment to the current document (the header's New Comment: on a plan's Read view, not archived; nothing otherwise)
    - Ctrl+PgUp: Focus previous tab, wrap/loop to last
    - Ctrl+PgDown: Focus next tab, wrap/loop to first
    - Ctrl+Home: Focus first tab
    - Ctrl+End: Focus last tab
    - In a browser Ctrl+PgUp, Ctrl+PgDn and Ctrl+Shift+T are Chrome's own and never reach the page; in the desktop they are ours. So each has a second binding that a browser lets through: Alt+PgUp, Alt+PgDn, Alt+Home, Alt+End for the tabs and Ctrl+Shift+H for the threads; the Hotkeys page lists both. In the editor Ctrl+Home and Ctrl+End are Monaco's, and the tab keys yield to it.

- When a plan tab is detached and displayed in its own window, there needs to be a way to toggle the visibility of the threads panel. Currently, the detached window inherits the current threads panel visibility with no way to toggle it. A threads toggle goes in the detached bar beside Re-attach (Ctrl+Shift+T works there too); a detached window keeps its ThreadsHidden in memory only, starting from the shared remembered value, so the two windows do not write over each other's setting.

- Clicking on anchor text in the plan view will select the associated thread, however, we have no way to deselect the current thread. make it so that clicking outside of any anchored text will deselect the current thread.
